# Button

Triggers an action with a visible label. Import `Button` from `bench-design`
and load `bench-design/styles.css` once in your application.

## Overview

<Canvas of={ButtonStories.Variants} />

## Usage

Use `primary` for the main action and `secondary` for supporting actions
(the default). Use only one `primary` per action area.

- Do use clear action labels, such as “Save” and “Cancel”.
- Do supply visible text and pass `isDisabled` from the application when needed.
- Avoid ambiguous labels and buttons without visible text.
- Use a link when navigating to a destination.

## TypeScript API

The table is generated from the TypeScript component, without a separate prop list.

`type` defaults to `button`; `submit` and `reset` retain native form semantics.
`onPress` is a callback without arguments. General HTML attribute passthrough
is not supported.

### Restore focus

The DOM ref lets the application restore focus without importing React Aria:

```tsx
const ref = useRef<HTMLButtonElement>(null);
<Button ref={ref}>Save</Button>
<Button onPress={() => ref.current?.focus()}>Restore focus</Button>
```

## Keyboard and ARIA

Tab reaches an enabled button; Enter and Space each trigger `onPress` once.
A disabled button cannot receive focus or trigger an action.
Keyboard focus uses `--bd-focus`.

Content normally supplies the accessible name. `aria-labelledby` takes
precedence over `aria-label`, which takes precedence over content. Prefer the
content alone when no additional context is needed.

An explicit accessible name must contain the visible label, preferably at its
start ([WCAG 2.5.3: Label in Name](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html)).
“Save the document” includes “Save”; “Confirm” replaces it and fails this rule.
The DS does not extract visible text or rewrite accessible names automatically.

```tsx
<Button aria-label="Save the document">Save</Button>

<span id="save-label">Save the document</span>
<Button aria-labelledby="save-label">Save</Button>
```

## Out of scope

Ghost and danger variants, compact sizes, loading, toggling and routing
are not provided. Business permissions, validation, form state and application
workflows belong to the consuming product.
