# Button

Déclenche une action avec un libellé visible. Importer `Button` depuis
`bench-design` et `bench-design/styles.css` dans l’application.

## Aperçu

<Canvas of={ButtonStories.Variants} />

## Quand l’utiliser

Pour déclencher une action ; `primary` désigne l’action principale et
`secondary` une action secondaire (valeur par défaut). Un seul `primary` par
zone d’action. Pour naviguer vers une destination, utiliser un lien.
Éviter les libellés ambigus et les boutons sans texte visible.

## API TypeScript

Table générée depuis le composant TypeScript, sans liste parallèle de props.

<ArgTypes of={ButtonStories} />

`type` vaut `button` ; `submit` et `reset` gardent leur sémantique native.
`onPress` est un callback sans argument. Aucun passthrough général.

Restaurer le focus avec la ref :

```tsx
const ref = useRef<HTMLButtonElement>(null);
<Button ref={ref}>Enregistrer</Button>
<Button onPress={() => ref.current?.focus()}>Rendre le focus</Button>
```

Compléter le nom accessible sans masquer le texte visible :

```tsx
<span id="save-label">Enregistrer le document</span>
<Button aria-labelledby="save-label">Enregistrer</Button>
```

## Clavier et ARIA

Tab atteint le bouton actif ; Entrée et Espace déclenchent `onPress` une fois.
Un bouton désactivé ne reçoit pas le focus et ne déclenche aucune action.
Le focus clavier utilise `--bd-focus`. La ref DOM permet au consommateur
l’appel `ref.current?.focus()` pour restaurer le focus.

Le contenu donne le nom accessible. `aria-labelledby` a priorité sur
`aria-label`, qui a priorité sur le contenu. Garder le texte visible dans le
nom calculé : « Enregistrer le document » complète « Enregistrer » ;
« Valider » le remplace et viole WCAG 2.5.3. Le DS ne réécrit pas les noms.

## Hors du périmètre

Ghost, danger, taille compacte, icône, chargement, bascule et routage ne sont
pas livrés. Les règles métier et workflows de formulaire appartiennent aux
produits.
