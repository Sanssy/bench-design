# Dialog

Import `Dialog` and `Button` from `bench-design`; load `bench-design/styles.css` once.

## Usage

Use for a focused task or a longer reading surface that interrupts the page. Supply a DS Button as the trigger, a concise title, body content and optional actions. For application-driven opening, supply `isOpen` and `onOpenChange`; `trigger` may then be omitted. Keep one control mode for the lifetime of the dialog. Avoid nested modals. Use Popover for contextual help.

## API

<ManifestProps component="Dialog" />

The optional eyebrow is metadata. Actions stay visible while the body scrolls. Action behavior belongs to the consumer; the built-in Close button and Escape dismiss the dialog.

Use `placement="end"` for a full-height sheet on the logical end edge (including RTL). It fills the screen below 640px. Use `size="wide"` for a wider reading workspace; the defaults remain `center` and `default`. The header stays visible while only the body scrolls. A rich `title` must contain meaningful text; keep interactive controls in the body or actions.

## Accessibility

The editorial heading names the dialog. React Aria contains focus, hides the background from assistive technology, handles Escape and restores focus to the trigger or the element focused before controlled opening. Tab and Shift+Tab cycle through dialog controls. The Close button is an icon action named “Close”. Appearance fades only when reduced motion is not requested. Test the reading order and focus sequence of your content.

Internal copy and numeric summaries follow the React Aria locale. Use the optional `BenchProvider` for English/French copy and partial message overrides; consumer labels remain application-owned.
