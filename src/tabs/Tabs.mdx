# Tabs

A named list of tabs and their associated content panels. Import `Tabs` from `bench-design` and load `bench-design/styles.css` once.

## Usage

Supply unique stable item identifiers, short titles and panel content. Use `defaultSelectedKey` for an initial selection, or `selectedKey` with `onSelectionChange` for application-controlled panels. Use `orientation="vertical"` for a side list. Keep routing and business state in the consumer. Do not use tabs for unrelated destinations. General `className` and `style` overrides are excluded.

For vertical lists, add a decorative `icon` and a short `description` to each item. The accessible name includes the title and description, even when the description is hidden on mobile. Keep both concise. `listWidth="sidebar-width"` uses the compact navigation token; `"panel-width"` uses the wider panel token. Omitting it preserves intrinsic sizing. `stickyList` keeps the list visible at 960px and above; document scrolling belongs to the consumer.

Below 640px, vertical lists become a chip grid: two columns for up to four items, three for five or six. Longer lists scroll horizontally. The vertical keyboard axis stays unchanged. Avoid long titles in compact grids.

## Keyboard and ARIA

Tab enters the selected tab. Left and Right arrows select adjacent tabs; Up and Down select adjacent tabs in vertical orientation; Home and End reach the first and last. React Aria connects tablist, tab and tabpanel roles, names and selection states. Keyboard focus uses the shared visible focus treatment.

## Framed side navigation

Use `variant="cards"` with vertical orientation for framed items and the shared selection shadow. `listHeader` and `listFooter` render outside the tablist, stick with the list and are hidden in the compact mobile grid. Keep these slots informational, without additional navigation controls.
